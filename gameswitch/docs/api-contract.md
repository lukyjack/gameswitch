# GameSwitch API contract

All JSON. Errors: `{error: string}`. Auth mutations require same Origin and `X-CSRF-Token` from session. Cookies are HttpOnly, SameSite Strict. UI is German. Runtime defaults to explicitly labelled sandbox; production adapter is PufferPanel.

- GET `/api/session` -> `{authenticated, setupRequired, csrfToken?, username?, mode: 'sandbox'|'pufferpanel'}`
- POST `/api/setup` `{token, username, password}` -> session. One-time local bootstrap token printed on first server run.
- POST `/api/login` `{username,password}` -> session (csrfToken included)
- POST `/api/logout` -> `{ok:true}`
- GET `/api/state` -> `{mode, profiles, activeProfileId, job, backups, events, host: {name,cpuCores,memoryMb,reservedMemoryMb}, security: {authenticated:true,csrf:true,localOnly:boolean}, catalog}`
- profile -> `{id,name,gameId,version,loader,modpackId?,modpackVersion?,modpackName?,modpackVersionName?,javaVersion?,minimumMemoryMb?,recommendedMemoryMb?,collectionId?,gamemode?,map?,maxPlayers,memoryMb,port,serverId?,installed,status:'stopped'|'running'|'unknown',createdAt}`. FTB metadata is resolved server-side, never trusted from client input. Loader includes `ftb`; GMod `gamemode` is `sandbox` or `terrortown`.
- catalog -> `[{id,name,description,kind:'minecraft'|'steam',loaders:string[],defaultPort,defaultMemoryMb}]`
- POST `/api/profiles` `{name,gameId,version,loader,modpackId?,modpackVersion?,collectionId?,gamemode?,map?,maxPlayers,memoryMb,port,eulaAccepted?}` -> `{profile}`. No arbitrary install commands/URLs/templates accepted. Server IDs generated by backend. FTB IDs are numeric strings with a fixed public release version. FTB Java heap minimum is enforced with an additional 2048 MB container allowance. Its maximum heap is capped at the pack recommendation when available; initial heap is at most 2048 MB.
- POST `/api/profiles/:id/activate` -> `{job}` (async install/switch with serialized global job lock)
- POST `/api/profiles/:id/stop` -> `{job}`
- POST `/api/profiles/:id/backup` -> `{job}` (only stopped; UI explains)
- POST `/api/backups/:id/restore` -> `{job}` (only stopped; retain pre-restore backup)
- GET `/api/profiles/:id/console` -> `{lines:string[]}`
- POST `/api/profiles/:id/console` `{command:string}` -> `{ok:true}`. Minecraft only, authenticated same-Origin/CSRF request, 30 commands/minute. One nonempty line, at most 1024 characters; control characters are rejected and an optional leading slash is removed. Requires a fresh running status and no lifecycle operation; the command holds the lifecycle gate until dispatch completes. Common top-level stop/restart verbs are rejected as a convenience, not a sandbox against arbitrary Minecraft/mod commands. This is an administrator console, never a shell. The audit records the verb without arguments before sending. Acceptance is not proof of game execution; inspect console output. An uncertain dispatch returns 502 and is never retried automatically.
- GET `/api/catalog/modpacks?q=...` -> `{hits:[{id,slug,title,description,downloads,versions:string[]}]}` Modrinth only
- GET `/api/catalog/modpacks/:id/versions` -> `{versions:[{id,name,version,gameVersions,loaders}]}`
- GET `/api/catalog/ftb?q=...` -> `{hits:[{id,slug,title,description,downloads,versions,provider:'ftb'}]}` via fixed official FTB API.
- GET `/api/catalog/ftb/:id/versions` -> `{pack:{id,name},versions:[{id,name,version,gameVersions,loaders,javaVersion,minimumMemoryMb?,recommendedMemoryMb?}]}`. Only public release versions with supported Java runtimes.
- GET `/api/catalog/minecraft-versions` -> `{versions:string[]}`

job -> `{id,type,status:'running'|'completed'|'failed',profileId,steps:[{label,status:'pending'|'running'|'completed'|'failed'}],error?,createdAt}`
backup -> `{id,profileId,profileName,name,createdAt,status:'completed',runtimeId?}`
event -> `{id,time,level:'info'|'warning'|'error',message}`

Client polls state every 2 seconds during jobs, 8 seconds idle. UI is an honest control panel: no fabricated real CPU/players/uptime metrics; sandbox clearly labelled.
