# GameSwitch API contract

JSON except the authenticated Steam Server-Sent Events stream. Errors: `{error: string, errorId?: string, requestId?: string}`. Auth mutations require same Origin and `X-CSRF-Token` from session. Cookies are HttpOnly, SameSite Strict. UI is German. Runtime defaults to explicitly labelled sandbox; production adapter is PufferPanel.

Every request reaching GameSwitch receives a server-generated UUID in `X-Request-ID`; a supplied request-ID header is ignored. Handled server errors and uncertain console/admin delivery include `errorId` and `requestId` plus a safe message containing the error ID. With the default logger the error ID equals the originating request ID. Ordinary validation/authentication/conflict errors can still contain only `error`. These IDs correlate private diagnostics; they do not grant access to logs or trigger retries. No diagnostics-reading API is implemented.

- GET `/api/session` -> `{authenticated, setupRequired, csrfToken?, username?, mode: 'sandbox'|'pufferpanel'}`
- POST `/api/setup` `{token, username, password}` -> session. One-time local bootstrap token appears in the development console; production writes it privately to `DATA_DIR/setup-token`.
- POST `/api/login` `{username,password}` -> session (csrfToken included)
- POST `/api/logout` -> `{ok:true}`
- GET `/api/steam/setup/status` -> `{enabled:boolean,active:boolean,session?:{id,gameId,startedAt,state:'starting'|'running'|'finished'|'failed'|'cancelled'},reason?:string}`. Safe metadata only; no credentials or terminal history. Missing/untrusted local broker is reported as disabled.
- POST `/api/steam/setup/start` `{gameId:'arma3'|'dayz',workshopIds?:string[]}` -> `{session}` (201). Same-Origin/CSRF/authenticated administrator, existing command-rate limit, at most 30 distinct numeric Workshop IDs; no username/password in the start body. Refuses an unhealthy store or active game lifecycle job. Persists only a fixed audit event naming the game before requesting the dedicated local broker. One setup at a time. While setup is active, profile lifecycle/restore requests are held with 409; Steam setup never switches a running game itself.
- GET `/api/steam/setup/:id/events` -> `text/event-stream`, `Cache-Control: no-store`. Each SSE `data:` is JSON `{type:'started'}`, `{type:'output',data:<base64 PTY bytes>}`, `{type:'exit',code:number}` or `{type:'error',reason:<fixed vocabulary>}`. UUID session ID, authenticated cookie, same-Origin/cross-site check and bounded output/backpressure. Logout, replacement login or session expiry invalidate access to the stream; closing a browser stream alone does not stop the setup. The Node process keeps only a bounded in-memory event buffer, not a persistent console log. The UI renders escaped plain text and strips terminal control sequences.
- POST `/api/steam/setup/:id/input` `{input:string}` -> `{ok:true}`. Same-Origin/CSRF/auth, command-rate limit, at most 512 UTF-8 bytes, one line without control characters. Leading/trailing spaces are preserved; empty input sends Enter. The broker appends exactly one newline. Accountname/password/Steam Guard are entered only when the current SteamCMD prompt requests them. Neither request bodies nor credential input are audited or returned. Uncertain delivery returns 502 and is never retried automatically.
- POST `/api/steam/setup/:id/cancel` `{}` -> `{ok:true}`. Same-Origin/CSRF/auth and separate cancellation-rate limit. Ends only the setup session owned by this bridge; existing game containers are never targeted. Panel restart or loss of its Unix-broker connection also cancels its setup helper. Closing the modal merely clears its transient browser input/output and permits reopening the current session.
- GET `/api/state` -> `{mode, profiles, runningProfileIds, activeProfileId, pendingSafetyBackupProfileIds, job, backups, events, host: {name,cpuCores,memoryMb,reservedMemoryMb}, security: {authenticated:true,csrf:true,localOnly:boolean}, catalog, runtimeSetup: {arma3,dayz}}`. `runningProfileIds` lists all confirmed running profiles. `activeProfileId` is a compatibility field containing the first running ID or `null`. `pendingSafetyBackupProfileIds` lists profiles whose required backup is still outstanding. Each setup entry is `{ready:boolean,reason:string,workshopIds:string[],simulated?:boolean,updatedAt?:string}` and describes the prepared server files and Workshop items. Sandbox entries are explicitly simulated. No Steam username, password, session or private file path is exposed.
- profile -> `{id,name,gameId,version,loader,modpackId?,modpackVersion?,modpackName?,modpackVersionName?,javaVersion?,minimumMemoryMb?,recommendedMemoryMb?,collectionId?,gamemode?,map?,mission?,workshopIds?,adminSteamIds?,worldName?,queryPort?,beaconPort?,maxPlayers,memoryMb,port,serverId?,installed,status:'stopped'|'running'|'unknown',createdAt,serverPasswordSet?,rconPasswordSet?,consoleInput,adminKind}`. FTB metadata is resolved server-side. GMod `gamemode` is `sandbox` or `terrortown`. Secret values are excluded by an explicit response-field allowlist.
- catalog -> `[{id,name,description,kind:'minecraft'|'steam'|'native',loaders:string[],defaultPort,defaultMemoryMb,available,consoleInput,adminKind,minMemoryMb,maxPlayers,defaultVersion?,defaultQueryPort?,defaultBeaconPort?,notice?,unavailableReason?}]`. Nine entries: Minecraft, GMod, Arma 3, DayZ, Squad, Valheim, Terraria, Factorio and FS25. Arma/DayZ profile creation is enabled; activation additionally requires trusted prepared files and all selected mods. Squad and FS25 are visible with blocking reasons; creation and activation remain unavailable.
- POST `/api/profiles` `{name,gameId,version,loader,modpackId?,modpackVersion?,collectionId?,gamemode?,map?,mission?,workshopIds?,adminSteamIds?,worldName?,queryPort?,beaconPort?,serverPassword?,maxPlayers,memoryMb,port,eulaAccepted?}` -> `{profile}` (201). No arbitrary install commands/URLs/templates accepted. Server IDs are generated by the backend. `serverPassword` is required for Valheim/Factorio/Arma 3/DayZ, 8–64 ASCII letters/digits/underscore/hyphen, and written only to the private secret store. `worldName` is limited to 1–40 letters/digits/underscore/hyphen. Steam games use `latest`; native versions are pinned to Terraria 1.4.5.8 and Factorio 2.1.24. Validate each game's RAM/player limits and complete port range, including reserved administration ports and secondary ports. FTB IDs pin a public pack release; Java heap minimum includes an additional 2048 MB container allowance, maximum heap is capped at the pack recommendation, and initial heap is at most 2048 MB.
- POST `/api/profiles/:id/parallel` `{}` -> `{job}` (202). Starts a stopped profile and installs it if needed. The job checks host-port bindings and the sum of configured RAM limits for the target and running profiles against `host.memoryMb - host.reservedMemoryMb`. A pending safety backup for the target must complete before start. Arma and DayZ also require the prepared host library and selected Workshop items. Other running profiles keep running. `/api/profiles/:id/activate` is a legacy alias for this endpoint and returns a `parallel` job.
- POST `/api/profiles/:id/switch` `{sourceProfileId:string}` -> `{job}` (202). The URL names the target. The source ID is a UUID and must identify the sole running profile. The target must be stopped and eligible to start. After validating the target and completing any outstanding backup for it, GameSwitch saves, stops and backs up the source before installing or starting the target. A stale source selection fails before any stop action. The job has type `activate` and records `sourceProfileId`.
- POST `/api/profiles/:id/restart` `{}` -> `{job}` (202). Requires a running, installed target with no incomplete restore. The serialized job persists the target's safety obligation, saves, gracefully stops, explicitly confirms stopped status, completes a full `Vor-Neustart` backup and starts the same profile without reinstalling it. Saves, stops, status checks and backups must succeed before start. The job reports that the process started. Game readiness is checked separately. Nonempty request bodies are rejected.
- POST `/api/profiles/:id/update` `{}` -> `{job}` (202). Applies to installed Arma 3 and DayZ profiles. Nonempty bodies are rejected. The job checks the library, selected Workshop items, private settings and capacity for the target before updating it. A running target is saved and stopped with a recorded safety obligation. After a full `Vor-Update` backup, the runtime re-applies the current fixed definition (`PUT /definition`) and its install steps from the prepared library. It refreshes server files and default mission files and rebuilds `mods/` and `keys/`. It keeps persistence, `profiles/` and existing configs. A previously running target starts again after a successful update. A target that was already stopped stays stopped. `profile.libraryUpdatedAt` records the library version used.
- POST `/api/profiles/:id/stop` -> `{job}` (202). Saves and gracefully stops the selected running profile, then completes its safety backup. A failed or interrupted backup leaves a durable obligation for that profile. A stopped profile's obligation can be cleared by successfully backing it up.
- POST `/api/profiles/:id/backup` -> `{job}` (only stopped; UI explains)
- POST `/api/backups/:id/restore` -> `{job}` (only stopped; retain pre-restore backup)
- GET `/api/profiles/:id/console` -> `{lines:string[]}`
- POST `/api/profiles/:id/console` `{command:string}` -> `{ok:true}`. Minecraft, GMod, Terraria and Factorio; the Squad transport is prepared but that game is unavailable. Valheim, Arma 3 and DayZ have output only; direct command requests are rejected. The Source/TCP RCON adapter is not reused for Arma/DayZ. Authenticated same-Origin/CSRF request, 30 commands/minute; one nonempty line of at most 1024 characters without control characters. An optional leading slash is normalized; Factorio receives exactly one leading slash. Other games also reject semicolons and quoted command names. Requires a fresh running status and the exclusive lifecycle gate. Common top-level lifecycle verbs are rejected as a convenience, not a sandbox against arbitrary game/mod commands. The audit persists only the verb before dispatch. Acceptance is not proof of game execution. An uncertain dispatch returns safe 502 wording and is never retried automatically.
- POST `/api/profiles/:id/admin` `{steamId:string,role:'admin'|'superadmin'|'user'}` -> `{ok:true,notice:string,requiresRestart:boolean,simulated?:boolean}`. Shares authentication, CSRF, Origin, command rate, durable argument-free audit and lifecycle gate. Strictly canonicalizes SteamID2/SteamID64 for public individual accounts; usernames and extra fields are rejected. GMod requires an installed, running profile with ULX/ULib; emits one fixed `ulx adduserid ... admin|superadmin` or `ulx removeuserid ...` command. Valheim accepts `admin|user` only, requires a confirmed stopped profile, backs up and merges `saves/adminlist.txt` using `Steam_<ID64>`, preserving other entries. Arma 3 accepts `admin|user` only and updates the fixed included `arma/admins.cfg` fragment at confirmed stop; administrators use `#login` in-game after the next normal start. Neither helper restarts the game. Prepared Squad support merges only its managed `GameSwitch_Admin` assignment in `Admins.cfg`, but is not a launchable game. DayZ accepts `admin|user` only for profiles that load VPPAdminTools (`1828439124`, after CF `1559212036`): at confirmed stop it creates `profiles/VPPAdminTools/Permissions/SuperAdmins` if needed, backs up and rewrites `SuperAdmins.txt` with one SteamID64 per line (VPP's own placeholder line is dropped, unexpected content blocks the edit). Vanilla DayZ profiles reject this action. File-write uncertainty returns 502 without automatic repetition. Minecraft uses `op Name`/`deop Name` through its console; Factorio uses `/promote ExactPlayerName`; vanilla Terraria has no equivalent operator role.
- POST `/api/profiles/:id/admin-password` `{password:string}` -> `{ok:true,notice,requiresRestart,profile}`. DayZ only; 8–32 ASCII letters/digits/underscore/hyphen. Same authentication, CSRF, Origin, rate limit and lifecycle gate as the admin helper. Installed profiles require a confirmed stop: the runtime replaces exactly one `passwordAdmin` assignment in `gameswitch-dayz/serverDZ.cfg` (local changes elsewhere stay) and, with VPPAdminTools, writes the plain password as first line of `profiles/VPPAdminTools/Permissions/credentials.txt`, which VPP hashes on its next start. Only after confirmed writes the value is stored in the private secret store; not yet installed profiles store it for the first install. Events contain no password or Steam ID; `adminPasswordSet` is the only exposed flag.
- GET `/api/catalog/modpacks?q=...` -> `{hits:[{id,slug,title,description,downloads,versions:string[]}]}` Modrinth only
- GET `/api/catalog/modpacks/:id/versions` -> `{versions:[{id,name,version,gameVersions,loaders}]}`
- GET `/api/catalog/ftb?q=...` -> `{hits:[{id,slug,title,description,downloads,versions,provider:'ftb'}]}` via fixed official FTB API.
- GET `/api/catalog/ftb/:id/versions` -> `{pack:{id,name},versions:[{id,name,version,gameVersions,loaders,javaVersion,minimumMemoryMb?,recommendedMemoryMb?}]}`. Only public release versions with supported Java runtimes.
- GET `/api/catalog/minecraft-versions` -> `{versions:string[]}`

job -> `{id,type,status:'running'|'completed'|'failed',profileId,sourceProfileId?,steps:[{label,status:'pending'|'running'|'completed'|'failed'}],requestId?,errorId?,error?,createdAt}`. Lifecycle jobs share a global operation lock. A competing request receives 409. API-created jobs retain the initiating request ID. Failed jobs return a fixed, classified message with `Fehler-ID` and `errorId` in state. The recorded diagnostic reasons `port_conflict`, `memory_capacity` and `switch_source_changed` identify port overlap, insufficient RAM budget and a stale switch source respectively.
backup -> `{id,profileId,profileName,name,createdAt,status:'completed',runtimeId?}`
event -> `{id,time,level:'info'|'warning'|'error',message}`

Client polls state every 2 seconds during jobs, 8 seconds idle. UI is an honest control panel: no fabricated real CPU/players/uptime metrics; sandbox clearly labelled.

## Arma 3 and DayZ typed profile fields

`workshopIds` is an optional ordered array of at most 30 distinct strings matching `[1-9][0-9]{4,19}`. It accepts individual numeric Workshop IDs, not collection URLs, arbitrary paths, launch options or an uploaded HTML preset. The selected items and their dependencies must first be prepared by the host administrator. `mission` and `workshopIds` are rejected on other games; GMod keeps its separate Collection field.

Arma `mission` is one of `MP_COOP_m01.Stratis` (default), `MP_COOP_m03.Altis`, `MP_ZGM_m11.Altis`, `MP_ZGM_m12.Stratis` or `MP_CombatPatrol_01.Altis`. `adminSteamIds` is Arma-only: at most 20 distinct, valid public individual SteamID64 strings of exactly 17 digits. Arma derives five consecutive UDP ports starting at `port` (default 2302); minimum profile RAM is 4096 MB, default 6144 MB, at most 32 configured slots. Mission slots may impose a lower limit.

DayZ initially accepts only `dayzOffline.chernarusplus`. It publishes UDP `port` through `port+2` and a separate `queryPort` (default 27016). Minimum RAM is 4096 MB, default RAM is 8192 MB and the profile supports up to 40 configured slots. Arma missions are rejected for DayZ. Optional `adminPassword` (DayZ only, 8–32 characters as above) becomes `passwordAdmin` for `#login` and, with VPPAdminTools, the VPP menu password. VPPAdminTools (`1828439124`) and Community Online Tools (`1564026768`) require Community Framework (`1559212036`) earlier in `workshopIds`; VPPAdminTools also requires `adminPassword`. DayZ `adminSteamIds` (max 20) require VPPAdminTools and seed `SuperAdmins.txt` on the first install. DayZ runs in the locally built `gameswitch.invalid/dayz-runtime:1` image (steamcmd plus libcurl/libcap); its install step fails with the missing library names if `ldd DayZServer` reports any. These resource limits are product budgets, not player-capacity guarantees.
